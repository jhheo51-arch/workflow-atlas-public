# 운영 변경 승인과 복구 도구 RFP 예시

가상 발주와 응답 예시입니다. 공개 OptiMesh 시제품을 바탕으로 업체 비교와 인수 검수 조건을 설계했습니다. 실제 발주, 납품, 운영 검수 기록은 없습니다. [OptiMesh 공개 사례](https://github.com/jhheo51-arch/jhheo51-arch/blob/main/portfolio/optimesh/CASE-APPROVAL-RECOVERY-20261123-v1.md)

## 문제 정의

운영 담당자가 여러 도구의 변경안을 검토할 때 승인하지 않은 값이 바뀌거나, 복구 중 다른 사람이 바꾼 값이 덮어써질 수 있습니다. 범위는 변경 대상 검토, 선택 승인, 실행 후 확인과 복구입니다. 전사 운영 배포와 기존 시스템 교체는 이 시범 과업의 범위 밖입니다.

## 제안 요청과 검수

모든 제안사는 가상 자원 5개를 공통 입력으로 사용합니다. 재현 가능한 시연 절차와 결과 기록을 ID별로 제출합니다. 아래 검수는 발주자가 합의된 테스트 계정에서 다시 수행합니다.

| ID | 구분 | 요구사항 | 제안 증빙 | 구축 후 검수 |
| --- | --- | --- | --- | --- |
| R-01 | 필수 | 선택 승인한 항목만 변경 | 시연 전후 값과 항목별 실행 기록 | 5개 중 3개 승인 시 선택한 3개만 바뀌고 미선택 2개는 원래 값 유지 |
| R-02 | 필수 | 권한 없는 역할의 승인 차단 | 역할별 권한표와 차단 기록 | 기획자 역할로 높은 위험 변경 승인 시도 시 거절되며 자원 상태 유지 |
| R-03 | 필수 | 변경 후 독립적으로 값을 다시 조회하고 결과 기록 | 변경 요청과 별도 조회의 입력 및 결과 | 조회 값이 변경 기대값과 일치하고 실패 조건을 기록에서 확인 |
| R-04 | 필수 | 명시적 복구와 외부 변경 충돌 처리 | 일반 복구와 다른 변경이 끼어든 경우의 실행 기록 | 정상은 원래 값으로 복구, 충돌은 복구 보류 및 외부 변경 값 유지 |

제안 평가에서는 필수 ID별 시연 증빙을 대조합니다. 누락된 필수 증빙의 보완 허용 여부, 제안서 질의와 제출 기한, 테스트 계정의 범위, 예산, 가점과 배점은 발주 전 [확인]입니다. 최종 인수는 위에 적은 검수 결과와 승인 담당자 확인을 근거로 판단합니다.

### 예시 가점표

필수 증빙을 통과한 제안만 비교합니다. 배점은 가상 예시이며 실제 접수 전에 확정합니다. 각 항목은 0점(증빙 없음), 1점(일부 충족), 2점(충족)으로 매기고, 점수를 2로 나눈 뒤 가중치를 곱해 합산합니다.

| 평가 항목 | 연결 ID | 가중치 | 2점 기준 |
| --- | --- | --- | --- |
| 변경 확인과 기록의 재현성 | R-01, R-03 | 40% | 다른 평가자가 같은 가상 입력으로 전후 값과 조회 기록을 재현할 수 있음 |
| 권한과 충돌 대응 설명 | R-02, R-04 | 35% | 권한표와 충돌 시 조치가 시연과 운영 인수 문서에 서로 맞음 |
| 운영 인계 계획 | R-04 | 25% | 정상 복구와 복구 보류가 각각 누가 수행하고 어디에 기록되는지 설명함 |

## 예시 응답 대조

여기서는 공개 시제품 자료의 지원 범위를 가상 입찰 검토에 대입했습니다. 발주 예시가 테스트 계정 현장 재현을 요구하므로 모의 환경 기록만으로 최종 충족을 확정할 수 없습니다.

| ID | 응답 판단 | 확인 근거 | 남은 조치 |
| --- | --- | --- | --- |
| R-01 | 부분 충족 | 로컬 모의 환경에서 5개 중 승인한 3개만 변경된 기존 수락 기록 | 운영 담당 역할과 테스트 계정에서 전후 값 대조 |
| R-02 | 부분 충족 | 로컬 모의 권한에서 기획자의 높은 위험 변경 승인을 차단한 기존 기록 | 실제 연결 계정 역할 매핑과 차단 시험 |
| R-03 | 부분 충족 | 모의 환경 재진단에서 부분 승인 뒤 2개 이슈가 남은 기존 기록 | 테스트 계정에서 별도 조회와 실패 기록 검수 |
| R-04 | 부분 충족 | 모의 환경에서 5개 전체 변경 뒤 원래 값으로 복구한 기존 기록 | 별도 변경이 끼어든 충돌 시나리오를 테스트 계정에서 실행 |

## 결과 검토

**사용 제한**

공개 시제품 기록은 모의 환경의 일부 동작을 보여 줍니다. 실제 SaaS 권한, 동시 변경 충돌, 운영 복구 효과는 미확인입니다. 가상 발주 요구와 평가 조건은 예시입니다.

**앞으로 추진**

발주 담당자가 테스트 계정과 필수 증빙 처리 기준을 먼저 확정합니다. 운영 담당자는 권한이 제한된 환경에서 각 시나리오를 실행합니다. 승인한 범위의 값과 기록을 대조하고 충돌 시 보류가 확인되면 해당 환경의 검수를 완료합니다.
