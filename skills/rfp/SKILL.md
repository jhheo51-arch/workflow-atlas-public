# RFP 작성과 대응

먼저 사용자가 발주 문서를 만드는지, 받은 문서에 응답하는지 확인한다. 기존 사업계획, PRD, 테스트 기록, 공고문, 첨부와 정정본을 확인한다. 받은 문서의 제출 지침과 최신 정정 내용을 우선하고, 문서 사이에 충돌하면 원문 위치를 남겨 질의 항목으로 올린다.

## 발주용 제안요청서

1. 어떤 사용자의 어떤 업무를 바꾸며 어떤 결과를 인수할지 정한다. 포함 범위, 제외 범위, 외부 연동과 운영 주체를 적는다. 승인된 예산, 일정, 접수처만 확정 기재하며 빈 값은 [확인]으로 두고 필요한 질문을 적는다.
2. 업무 흐름의 정상, 예외, 권한 경계를 관찰 가능한 요구사항으로 나눈다. 항목 하나에 ID 하나를 붙이고 **ID, 필수/선택, 상황과 기대 동작, 제출 증빙, 검수 조건, 근거**를 적는다. 권한, 데이터, 인수인계, 변경과 복구는 과업에 해당할 때 요구사항으로 만든다.
3. 모든 업체에 같은 데모 입력과 응답 양식을 제공한다. 가격을 비교할 때는 같은 계약 기간과 과금 단위로 초기 구축비, 반복 비용, 지원과 이관 비용을 받는다. 필수 통과와 가점 채점을 구분하고 평가 기준과 가중치는 제안서 접수 전에 확정한다. 누락 증빙 처리와 배점을 문서에 적고, 가중치 합계와 요구 ID 연결을 대조한다.
4. 사업 배경, 범위와 산출물, 요구사항 표, 제출 및 질의 절차, 업체 공통 응답 양식, 평가 기준, 계약 후 검수를 작성한다. **제안 단계에서는 제출물을 평가하고, 구축 후에는 합의한 환경과 데이터로 검수한다.** 두 단계의 완료 기준을 각각 적는다.

## 기존 RFP 응답

1. 원문의 요구 ID, 제목, 위치를 유지하고, ID가 없으면 추적용 ID를 붙여 원문 위치와 연결한다. 제출 형식, 기한, 필수 첨부, 질의 절차도 대응표에 포함한다.
2. 각 행에 **충족/부분 충족/미충족/확인 필요, 현재 증빙과 확인 환경, 남은 차이, 담당 역할, 답변 위치**를 적는다. 구현 예정과 기존 기능을 구분한다. 실서비스 근거를 요구할 때 모의 환경 증빙은 그 범위를 적는다. 필수 미충족이나 미확인은 앞에 올려 질의, 보완 또는 참여 판단에 넘긴다.
3. 발주자가 지정한 순서와 서식으로 답안을 작성한다. 요구사항을 해석할 때 모호하거나 자료가 부족하면 원문을 인용할 위치와 확인 질문을 남긴다. 예산, 인증, 실적, 기능과 납기 약속은 자료에 근거해 작성한다.

## 전달 전 대조

- 빠진 필수 항목, 중복 ID, 근거가 없는 참조를 확인한다. 발주 초안에서는 모든 필수 ID에 증빙과 검수 방법이 있고 평가 기준이 요구사항에 연결돼 있어야 한다. 응답 초안에서는 원문 항목별로 답변 위치 또는 남은 조치가 있어야 한다.
- 누락 자료와 확정할 값을 한곳에 모은다. 실제 공고나 응답 제출은 담당자의 승인 범위에 따라 진행한다.
