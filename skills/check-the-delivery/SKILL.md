# 결과 전달 전 검증

1. 작업 요청과 최종 변경 내역을 대조합니다. 이미 있던 파일이나 링크가 바뀌었다면 의도한 변경인지 확인합니다.
2. 사용자가 여는 실제 시작점에서 끝까지 따라갑니다. 공개 링크는 방문자가 접근할 수 있는지, 수정한 흐름은 예상 결과를 화면이나 출력에서 확인할 수 있는지 점검합니다.
3. 오류나 빈 입력이 결과에 영향을 주는 기능이라면 대표 입력 하나로 실패 동작을 확인합니다. 실제 환경에 접근할 수 없으면 검사한 환경과 접근이 필요한 지점을 기록합니다.
4. 결과를 전달할 때 사용자가 열 수 있는 위치, 직접 확인한 결과, 아직 확인하지 못한 조건을 적습니다.

예를 들어 모의 데이터로 설정 변경을 시험한 결과라면, 실제 서비스 계정에서의 동작과 구분하고 사용자가 따라갈 수 있는 확인 경로를 남깁니다.
